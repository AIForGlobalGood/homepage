# Contributing

Thanks for even thinking about it. We're small and new, which means a single thoughtful contribution can shape a lot.

Before anything else, please read:
- [CHARTER.md](CHARTER.md) — what we are, what we won't do
- [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) — how we treat each other
- [PLAN.md](PLAN.md) — what we're working on and in what order

---

## Ways to contribute

### Propose a project
Open an issue using the **Project proposal** template (coming soon; until then, just open a regular issue titled `Project proposal: <name>` and describe the problem, the people it affects, the approach, and the risks).

How a proposal becomes a page is described in [PLAN.md — How a project becomes a project page](PLAN.md#how-a-project-becomes-a-project-page).

### Volunteer time or skills
Open an issue titled `Volunteer: <your skill or interest>`. Design, writing, translation, accessibility review, research, partner outreach, code — all welcome.

### Partner with us
If you work for an NGO, research group, or community organization and want to collaborate, open an issue titled `Partner inquiry: <your org>` or email the maintainers.

### Fix something you see
Typos, broken links, unclear writing, accessibility issues — just open a PR. No issue needed for small fixes.

### Report a Code of Conduct concern
See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Report privately to the maintainers.

## Licensing

By contributing, you agree that:
- Code contributions are licensed under the [MIT license](LICENSE).
- Written content (prose, docs, project pages) is licensed under [CC BY 4.0](LICENSE-CONTENT).

If you're submitting something that isn't yours to license — code copied from elsewhere, images under a different license, partner-owned material — flag it clearly in your PR so we can review.

---

## Writing style

- Short sentences. Plain words. No jargon the reader hasn't earned.
- Honest about what's a plan vs. what's shipped. Mark proposals as proposals.
- Don't overclaim impact. Don't understate risks.
- When in doubt, read a line out loud. If it sounds like a brochure, rewrite it.

---

## PR expectations

- One focused change per PR.
- Explain the *why*, not just the *what*, in the description.
- If the change touches [CHARTER.md](CHARTER.md), [PLAN.md](PLAN.md), or anything about the organization's name, independence, or governance, please open an issue to discuss first.
- Be patient with reviews. We're volunteers.

---

## What we won't accept

Grounded in [CHARTER.md](CHARTER.md), we won't accept contributions that:
- enable weapons, mass surveillance, deception/manipulation at scale, or discrimination;
- introduce dependencies on proprietary services where an open alternative exists and is practical;
- compromise user privacy, accessibility, or performance beyond what the project genuinely requires;
- misrepresent the organization's affiliations or status.

If you're unsure, open an issue and ask. That's always fine.
